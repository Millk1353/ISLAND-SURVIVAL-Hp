# ISLAND SURVIVAL V42

## تغييرات أساسية
- لا يوجد إنشاء ردهة من داخل اللعبة، وتم حذف endpoint العام لذلك.
- اللاعب يرى الردهـات العامة ويدخلها فقط.
- إنشاء الردهـات من لوحة/برنامج خارجي عبر `POST /api/admin/lobbies` مع ترويسة `x-admin-key`.
- الحساب يعتمد اسم مستخدم + كلمة مرور + بريد إلكتروني مؤكد.
- التسجيل يرسل رمزًا عشوائيًا من 6 أرقام، صالحًا 10 دقائق، مع حد 5 محاولات وإعادة إرسال بعد 60 ثانية.
- لا يُصدر Token ولا يسمح بالدخول قبل تأكيد البريد.
- اسم اللاعب داخل السيرفر هو اسم الحساب، وليس اسم عرض يختاره اللاعب.
- بيانات المخزون والتقدم محفوظة بمفتاح `lobby:<id>` ثم `accountId`؛ لذلك كل سيرفر له تقدم منفصل للحساب نفسه.

## إعداد البريد
الخادم يستخدم Resend API عبر HTTPS. اضبط متغيري البيئة:
- `RESEND_API_KEY`
- `EMAIL_FROM` (عنوان من نطاق موثّق داخل Resend)

لا تضع مفتاح البريد أو `ADMIN_API_KEY` في ملفات الواجهة أو GitHub. اضبطهما كـ Secrets/Environment Variables في منصة الاستضافة. من دون إعداد البريد سيرفض التسجيل برسالة واضحة، ولن ينشئ حسابًا غير مؤكد.

## إدارة السيرفرات من خارج اللعبة
طلب إنشاء ردهة:
```http
POST /api/admin/lobbies
Content-Type: application/json
x-admin-key: YOUR_ADMIN_API_KEY

{"name":"ردهة البقاء 0004","mode":"survival","max":20,"private":false}
```
لا يوجد زر إنشاء داخل اللعبة ولا endpoint إنشاء عام. لا تعرض مفتاح الإدارة في تطبيق اللاعب.

## ملفات البيانات الدائمة
اربط Volume دائمًا إلى `/app/data` في الاستضافة حتى لا تضيع الحسابات والعوالم عند إعادة تشغيل الحاوية.

## ملاحظات تشغيل
- Node.js 18+ (يوصى بـ Node 20).
- `npm start`
- `GET /api/health` يعرض `emailConfigured` للتحقق من إعداد البريد.
- يظل نشر عدة ردهات على حاوية واحدة محدودًا بموارد الاستضافة؛ `MAX_LOBBIES` حد منطقي وليس ضمانًا لقدرة فعلية.

## لوحة الإدارة الخارجية
افتح `https://عنوان-الخادم/admin` من متصفح المدير. أدخل عنوان API ومفتاح `ADMIN_API_KEY` لإنشاء السيرفرات. اللوحة منفصلة عن صفحة اللعبة، ومفتاح الإدارة لا يُضمّن في اللعبة. احمِ رابط اللوحة ومفتاحها ولا تنشرهما.
